# Security Policy

## Supported Versions

Only the latest stable release in the active 3.x major line receives security updates.

| Version | Supported          |
| ------- | ------------------ |
| Latest stable 3.x | :white_check_mark: |
| Earlier releases | :x:                |

## Reporting a Vulnerability

We take the security of **dbCMS** seriously. If you believe you have discovered a security vulnerability in dbCMS (including core framework integrations, Passport OAuth2 workflows, or native MCP server endpoints), please report it responsibly.

### How to report

**Please DO NOT report security vulnerabilities through public GitHub issues.**

Instead, please send an encrypted or direct email to:

📧 **`hola@davidbravo.com.es`**

Please include in your report:
- A detailed description of the vulnerability.
- Steps to reproduce the issue or a proof-of-concept (PoC).
- The affected component, endpoint, or configuration.
- Any potential remediation you may have identified.

### Coordinated Disclosure Timeline

The following are maintainer response targets, not guarantees enforced by the application or CI.

- **Initial Response**: We will acknowledge receipt of your vulnerability report within **48 hours**.
- **Assessment**: We will confirm the vulnerability and assess its severity, keeping you informed of our progress.
- **Remediation**: We aim to release a patch within **30 to 90 days**, depending on complexity and severity.
- **Public Disclosure**: A security advisory (CVE / GitHub Advisory) will be published alongside the patched release.

Thank you for helping keep dbCMS and its community safe!
